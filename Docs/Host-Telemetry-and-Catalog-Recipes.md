# Host telemetry and executable game recipes

This describes the unreleased Frost/telemetry candidate. It does not change Test45 or make a new Agent package available.

## In-place Agent delivery

Updating the panel and updating an enrolled Host Agent are separate operations. Use a matched signed release and the Host setup guide's **Update Host Agent** command when it is published. The supported Host command uses `--host --upgrade`, retains enrollment/configuration, and must run on the actual Host under the required account. Do not reinstall or wipe a Host to obtain metrics. This does not enable an update timer or operate a game.

The Agent negotiates process metrics and supported game adapters with the Controller. An older Controller gets its original fields and digest ceiling. An older Agent can keep managing its existing games but cannot report new measurements it does not collect. Rootless Podman remains the Linux container runtime.

## Process and shared Host readings

Shared Host readings concern the whole machine and system disk. Per-game CPU is in logical-core units (2.25 cores means 225% of one logical core); game RAM is process/container usage. Limits are shown only when actually reported. Missing, stale, offline or failed observations are not zero.

Podman counters are read only after exact container ownership/image/sandbox/confinement validation. Systemd-user CPU requires existing accounting counters and a warmed delta; Bifrost does not silently change service accounting configuration. Windows service CPU also needs consecutive compatible process-group samples. A process restart or accounting reset warms the counter again.

## Local game API policy

Add an explicit `gameQuery` to the approved Host profile, preserving its other fields. These examples show only the new property, not a replacement profile:

```json
{"gameQuery":{"adapter":"a2s","host":"127.0.0.1","port":27015}}
```

```json
{"gameQuery":{"adapter":"minecraft-bedrock","host":"127.0.0.1","port":19132}}
```

Use the actual locally reachable query port, including a correctly bound Podman mapping. Java uses `minecraft-java` and its enabled status port. Keen uses `space-engineers`, its enabled REST API port and a private `secretFile` on that Host. Never put the API secret in a browser field or submit a remote query URL. Unavailable queries are reported as unavailable; query support does not enable a vendor API automatically. Split/compressed A2S replies remain unsupported.

## Typed configuration policy

`operations.gameSettings` selects a whitelisted adapter and the actual relative configuration path under that instance's approved files root. The manager does not accept arbitrary Host paths or executable options.

| Adapter | Configuration basename |
|---|---|
| `minecraft-java`, `minecraft-bedrock` | `server.properties` |
| `space-engineers` | `SpaceEngineers-Dedicated.cfg`; optional separate world `Sandbox_config.sbc` |
| `palworld` | `PalWorldSettings.ini` |
| `source`, `rust` | `server.cfg` |
| `terraria` | `serverconfig.txt` |
| `ark` | `GameUserSettings.ini` |

For example, merge `"gameSettings":{"adapter":"rust","path":"server/identity/cfg/server.cfg"}` into the existing operations policy when that is the real instance-relative file. The actual basename is checked. Do not replace a complete policy with this fragment. Settings saves compare the file digest, preserve unknown/private options, stage the replacement and retain recovery evidence. Space Engineers server identity and loaded-world gameplay are separate scopes. The UI confirmation explains any restart needed to apply changes.

## Steam definitions and executable recipes

The frozen definition corpus and its provenance are in `profiles/steam-server-blueprints.json`. `scripts/import-steam-appinfo.py` merges bounded official SteamCMD observations; `scripts/import-linuxgsm-launches.py` supplements eight missing native launches from exact pinned public metadata without executing it. The pinned AMP import adds exact Windows launch facts for Blackwake, Ground Branch and Killing Floor. There are now 455 entries with launch metadata out of 471 definitions; 16 still lack a vendor launch. Ground Branch CTE is retired by its publisher in favor of Steam beta branches (https://www.groundbranch.com/about/faq/). Existing canonical labels and previously known launches are preserved. An upstream non-server art DLC is recorded as excluded, not treated as a game server.

`scripts/publisher/steam-game-manifests.mjs` selects a direct safe platform launch and parses bounded argv without a shell or variable expansion. An executable candidate needs an exact runtime image/config identity, supported platform, concrete ports, resources, writable data mounts, initial configuration and actual game readiness policy. Windows batch files cannot become Wine commands. The image's immutable `steam-server-appids` is regenerated by `generate-steam-runtime-policy.mjs`; arbitrary apps cannot be passed to SteamCMD.

The generic runtime keeps verified software read-only and writable worlds/configuration separate. Vendor scripts that require additional writes, SDK/runtime dependencies, terms or authenticated Steam access need concrete policy. An entry in a catalog is not a compatibility certificate. The old unsafe generic installer remains disabled.

`sign-game-catalog.mjs` accepts the existing exact hosted review or `verification.kind: "isolated-linux-artifacts"` with `networkServicesPaid: false`. The latter requires adjacent bounded regular JSON artifacts bound by `localEvidence.scan/smoke/layout` filenames and SHA-256 digests, exact manifest/image identities, a Trivy container-image report with no high/critical findings, non-root/read-only/no-new-privileges/zero-capability smoke results, and verified downloaded tree/required-file layout. It is an offline publisher integrity check, not permission to invent reports. The dedicated publisher key and all existing signature/Host approval checks remain required. Native Windows distribution still needs its separate package/Host acceptance route.
