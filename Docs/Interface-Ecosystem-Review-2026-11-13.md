## Human review versus generated captures

Capturing an image is not reviewing it. The complete initial Test42 render covered 296 master and 292 customer deep captures, 154/150 operational cases, eight workflows each, both 48-case global/audit control matrices and 24 submitted audit searches each. These unaffected layout/workflow/operational/search suites passed; the initial wrapper correctly failed the newly introduced brand-home accessible name. The failure remains retained.

Actual inspected Test42 screens include the original canonical mark; customer desktop/phone headers, overview, General and phone Backups; master overview, owner registry, workspace overview, rail footer and phone overview/menu. The prior broad task-flow review also inspected Settings/Appearance, Discord, audit, Files, Gate worlds, Deployment, backups and schedule creation; its scope is recorded in the Test41 report, not represented as fresh human inspection of every Test42 capture. The latest owner registry fits one row. Final phone review found the helper had served an old saved dist directory; it was pointed at the exact final build, recaptured and reviewed. The corrected image has left-aligned heading and single-line 44px actions. Old evidence is retained rather than silently rewritten as passing.

The native brand-home name, explicit visible-text spacing, one-row owner label and phone corrections were rebuilt on the final frozen source. Both full accessibility suites (75 master/73 customer states) and both 118-case search/shell/navigation/draft matrices pass across nine widths and six themes, with no API writes in read-only checks. The initial failed accessibility run is not claimed as green.

## Automated verification and operational limits

All application tests, builds, browser capture and package workloads ran in bounded isolated containers on existing authorized TROA server capacity. No paid services, GitHub runner requests, billing/limit changes or PC tests/builds/previews/dependency/WSL/container workloads. The PC handled source/Git/transport, small evidence and a small core-crypto manifest signature; the private signing key stayed offline.

- Full workspace build/types and final types pass. Application Node suite: 338 total, 334 pass, four optional skips. The Console and MFA real database cases pass separately. The other two nested rootless cases cannot mount proc under the verification container policy; these are not passes, and host protections were not relaxed.
- Public: 149 Python cases (146 non-root pass and three root cases passed separately), 66 Node cases; prerequisite14/world-helper4 pass. Dependency audit reports no known vulnerabilities.
- Real disposable database/API/migration, privilege, key rotation, owner MFA/license lifecycle, append-only audit and two-worker scheduled-operation dedupe/pause/delivery cases pass.
- Actual version42 compiled Linux Host archive and customer Controller/web owner/source exclusion pass. Three exact-image HIGH/CRITICAL plus secret scans find zero; complete SBOMs and image identities bind the evidence.
- Exact-image migrations twice and two authenticated PostgreSQL restores preserve account/password/MFA/recovery/Host/settings/journal state and original failed databases/keys. Compose lifecycle is simulated; this is not a real customer update.
- Website: 488 unit cases in 92 files, 72-page production build and final types pass. Its four command paths retain the gate, origin, no-store, HTTPS/size/hash checks and no wipe/reinstall UI.

Remaining owner acceptance: actual Debian/Ubuntu install and panel-only update/interruption recovery, Host preparation/resource enforcement, actual game/player/plugin/mod behavior, backup/restore, provider delivery, assistive technology and soak. Manual acceptance is explicitly false in the signed evidence. Existing customer installations, Host/game processes, timers, accounts/consent and notifications were not changed by verification. Finite deterministic tests cannot guarantee every environmental or usability outcome.
