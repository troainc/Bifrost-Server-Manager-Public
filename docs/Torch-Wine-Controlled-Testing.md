# Space Engineers Torch on Linux Wine: controlled testing

This target runs Torch, not vanilla Space Engineers. Bifrost downloads the official anonymous Steam App 298740 Windows depot and the exact hash-verified official Torch build. It runs them in a separate non-root, read-only Wine runtime; customer worlds, settings, logs and Wine state remain in writable `files/` storage. No game files, publisher signing key or Controller credentials are baked into that dependency image.

The reviewed candidate uses Torch `v1.3.1.347-master`, Wine 9, .NET Framework 4.8 and the reviewed Visual C++ dependencies. A fresh disposable sandbox downloaded Steam build `24675709` and reached `Keen: Game ready...`, including a new Wine prefix and Star System world with the actual Host's 64 MiB `/tmp`, UID 1000, dropped capabilities, read-only filesystem and 1024 PID ceiling. The image scan reported zero HIGH/CRITICAL vulnerabilities or detected secrets. The fixed Steam adapter refreshes application metadata before its allowlisted update; arbitrary commands and authenticated Steam-account prompts are not supported.

The dependency image is public and its exact digest/configuration were pulled anonymously. The six-target catalog is signed by the existing pinned publisher key; the five Java target records and signatures are unchanged. [Matched testing 15](https://github.com/troainc/Bifrost-Server-Manager-Public/releases/tag/v0.1.0-installtest.15) is published with matching Controller and Linux Host catalog. All 22 asset sizes/digests and nine anonymous downloads match; fresh HTTPS setup and compiled pairing/recovery passed. The immutable runtime publication record is [free public workflow 37578562603](https://github.com/troainc/Bifrost-Server-Manager-Public/actions/runs/37578562603). This is controlled testing evidence; real customer player connectivity, save/stop, restart, update rollback, backup/restore and failure recovery remain unverified.

## Test with matched testing 15

1. Install the matching Instance panel and Host Agent. Choose independent management or explicitly connect the Instance to your chosen Controller. Licensing remains a separate installation registration.
2. Under the separate game-service account, approve the exact bundled catalog and Host storage/resource policy. The online Host must advertise the reviewed Torch digest before Create is offered.
3. In the managing panel, choose **Space Engineers Â· Torch** and that Host. Allocate at least 8 GiB RAM, 3 CPUs and 40 GiB disk per instance, plus space for the runtime and backups; 4 CPUs were used in this review. Reserve the game's UDP port (default 27016) and Steam UDP port (default 8766).
4. Confirm placement. Bifrost downloads and inventories the server files, installs fixed initial settings and a separate writable world, then waits for Torch readiness. Steam's explicit `current` channel records the actual downloaded build; future builds are not automatically claimed compatible.
5. Verify a real player connection and world persistence, then save/stop/restart and recovery on your disposable Host. Keep custom Torch plugins and unreviewed runtime changes outside this initial test.

Controller URL/IP addresses carry authenticated management traffic. Player traffic goes directly to the chosen game Host's reserved ports. No customer game is created on TROA's licensing service by this flow. Windows native Torch, vanilla SE, Palworld and Bedrock keep their separate pending runtime/distribution acceptance; the existing five Java recipes retain their original signed identities.
