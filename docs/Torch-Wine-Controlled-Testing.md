# Space Engineers Torch on Linux Wine: controlled testing

Use the matched **Test27** customer package and Linux Host on Debian12 or Ubuntu24.04LTS x86_64. This target runs Torch. Bifrost downloads the official anonymous Steam App298740 Windows depot and the exact hash-verified official Torch build into a verified server tree. A separate non-root, read-only Wine runtime runs them; worlds, settings, logs and Wine state live in writable instance files. The dependency image contains no game files, publisher signing key or Controller credentials.

## Start a local game Host and Torch instance

1. Run the distribution-specific fresh Instance installer. Root prepares OS prerequisites and separate panel/game-service accounts; services run as non-root. Wait for **Local Host prepared**, then open the printed panel URL.
2. Select **Run independently**, create the initial administrator, finish MFA and current agreements, and activate licensing. Testing releases require a separate explicit authorization for disclosed license activation/check-ins. Analytics remains optional and off by default.
3. In **Connect your hosts** or **Hosts**, choose **Set up local Host** and explicitly approve the bundled signed game catalog. Wait for an authenticated online heartbeat. This is local Host approval; it does not require a remote Controller pairing code. Instance installations managed by another Controller retain their separate pairing/acceptance flow.
4. Open **Blueprints → Ready to install → Choose a host and install**, or **Game servers → Create instance**. Select **Space Engineers · Torch** and the compatible online Host. Review at least **6GiB RAM, 3CPUs and 20GiB free instance storage plus the 0.5GiB safety margin**. Leave additional resources/storage for the panel, dependency images, other games and backups. Prepared-package targets and incompatible/offline Hosts do not become executable choices.
5. Choose the game UDP port and Steam UDP port. Defaults remain27016 and8766;2750 is an operator choice, not a global default. The selected game port is written consistently into Torch, the container and host binding. Review the game terms and placement before confirming creation.
6. Follow the installation job until it succeeds and the game is ready. Players use the game Host's reachable address and selected port. Internet play needs matching router/firewall rules; panel and licensing URLs do not carry player traffic. Test an actual player join and world persistence on your disposable server.

The existing publisher identity and five Java recipe records stay unchanged. Wine/.NET/VisualC++ dependency layers are inherited from the reviewed Test22 image; the adapter update has its own exact image scan and actual fresh-world Torch startup evidence. Downloaded Steam `current` builds are inventoried and recorded, not assumed permanently compatible. New worlds are PUBLIC; existing worlds are preserved. Test27 final clean Ubuntu/Debian installation and selected-port UDP acceptance are recorded with the release; human player entry, native Windows service acceptance, broad update/restore and all-game acceptance remain separate.

Earlier Test15/Test22 evidence remains historical and immutable. It does not substitute for acceptance of the currently shipped runtime. Windows native Torch, vanilla Space Engineers, Palworld and Bedrock retain their distinct pending runtime/distribution gates. Keep custom plugins and unreviewed runtime changes outside the initial test.
